움직이는 화면은 쉽게 시선을 끈다. 하지만 시선을 끄는 것과 사용을 돕는 것은 다르다. 인터랙션을 설계할 때는 "어떻게 움직일까?"보다 "왜 움직여야 할까?"를 먼저 묻는 편이 좋다.

## 변화의 이유를 보여 주기

버튼을 눌렀을 때 색이 바뀌면 입력이 전달되었다는 것을 알 수 있다. 메뉴가 자연스럽게 열리면 새 내용이 어디에서 등장했는지 이해하기 쉽다. 이런 움직임은 화면의 상태를 설명한다.

반대로 모든 요소가 서로 다른 방향으로 날아온다면, 사용자는 내용을 읽기도 전에 움직임을 해석해야 한다. 한 화면 안에서는 방향과 속도를 일관되게 유지하는 것이 도움이 된다.

## 작은 움직임부터

호버 상태는 가장 작은 실험이다. 색상이나 테두리를 바꾸는 것만으로도 클릭할 수 있다는 단서를 줄 수 있다. 위치 변화가 필요하다면 몇 픽셀만으로도 충분하다.

```css
.project-card {
  transition: transform 200ms ease, border-color 200ms ease;
}

.project-card:hover {
  transform: translateY(-3px);
  border-color: var(--accent);
}

.project-card:focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 6px;
}
```

마우스를 쓰지 않는 방문자도 있다. 호버 효과가 전달하는 정보를 키보드 포커스에서도 확인할 수 있어야 한다. 중요한 설명을 호버할 때만 보여 주지 않는 것도 같은 이유다.

## 움직임을 원하지 않는 사람

지속적인 회전이나 큰 화면 전환은 일부 방문자에게 불편함을 줄 수 있다. 운영체제의 동작 줄이기 설정을 존중하면, 사용자가 선호하는 방식으로 화면을 볼 수 있다.

```css
@media (prefers-reduced-motion: reduce) {
  html {
    scroll-behavior: auto;
  }

  .project-card {
    transition: none;
  }
}
```

이 사이트의 첫 화면 그래픽은 해당 설정이 켜져 있으면 정지 상태로 시작한다. 별도의 일시 정지 버튼으로 방문자가 직접 선택할 수도 있다. 장식적인 움직임을 멈춰도 콘텐츠와 탐색 기능은 그대로 유지된다.

## 화면 밖에서는 쉬기

애니메이션은 보이지 않을 때도 계속 계산될 수 있다. 첫 화면의 그래픽을 이미 지나쳤다면, 그 계산을 유지할 이유가 줄어든다. 화면에 보이는지 관찰하고, 탭이 숨겨졌는지 확인해 필요한 순간에만 그리면 불필요한 작업을 줄일 수 있다.

중요한 것은 특정 기술을 썼다는 사실보다 실제 환경에서의 경험이다. 느린 기기와 작은 화면에서도 읽고 이동하기 편한지 확인해야 한다.

## 움직임은 문장의 구두점처럼

구두점이 모든 단어를 대신하지 않듯, 애니메이션도 콘텐츠를 대신하지 않는다. 필요한 순간에만 등장하고, 사용자의 다음 행동을 이해하기 쉽게 만드는 것. 그 정도의 역할만으로도 충분히 좋은 움직임이 될 수 있다.
